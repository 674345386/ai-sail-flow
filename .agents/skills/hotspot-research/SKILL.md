# 热点与创作选题研究

复用本项目已实现的工作流，不另建采集器或打分逻辑。接口和数据结构见 [工作流约定](../../../docs/radar-workflows.md)。本地服务默认是 `http://127.0.0.1:4317`；远程服务沿用现有登录认证。

- 先读取 `GET /api/studio/radar/config` 确认来源状态。`ready` 只代表可尝试采集，运行结果的 `success` 才代表本次连接取得响应。未配置或失败的来源必须在报告中说明。
- 通过 `GET /api/studio/radar/tools` 获取当前接口与 JSON Schema。根据任务选择 `top`、`product`、`breakout`、`resonance` 或 `calendar`，调用 `POST /api/studio/radar/run`；结果直接包含持久化 ID、来源状态、执行步骤、指标、证据缺口和 Markdown 报告。
- 用主题、品类或场景做反向探索。用户提供图片时可调用 `POST /identify`（multipart 字段 `image`），将识别出的可见线索作为可修改关键词；该步骤使用已配置的视觉模型。不要把图片识别结果当成热度证据。
- 用户已有平台导出时，通过 `POST /import` 导入；再用 `localOnly: true` 分析。保留真实来源 URL、采集时间和历史快照。收藏、分享、评论正文等拿不到就留空，不要推算或补造。
- 需要继续研究时读取 `/runs` 和 `/runs/:id`。需要基于已有证据提出创作假设时，可调用 `/runs/:id/interpret`；该步骤使用已配置的文本模型。默认规则报告不消耗模型调用。

热度和潜力是不同指标。潜力计算需要至少 5 个可比样本、可用互动指标，以及同一内容间隔至少 15 分钟的播放量快照。不得把多次立即调用当成历史趋势；不得将搜索量区间当作累计播放量求增速。具体计算始终复用 `shared/radar.ts`。

交付时区分观察事实、传播机制假设、创作建议和验证方法。关键判断引用已有证据编号与链接。未观看原视频或读取评论正文，就不声称已经分析钩子、节奏或讨论动机。指数不是爆款概率，不能用相关性证明传播因果。

本 Skill 不启动 Apify Actor、不发布内容、不创建监控任务；只有用户要求持续监控时才设计后续运行安排。
