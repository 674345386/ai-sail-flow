# 执行画布第二版复盘与第三版迭代

日期：2026-11-12。入口：`http://127.0.0.1:4317/lab` → 执行画布。

第二版围绕“看素材 → 写要求 → 引用 → 续做 → 查看结果”实现。以下“已实现”表示源码、领域行为或组件渲染已有对应实现，不等同于浏览器交互及真实生成已验收。视觉依据是用户提供的 Liblib 截图；没有下载或解析链接中项目的 HTML/CSS/JS，也没有实测其交互。

## 逐项核对

| 原定功能 | 第二版结果 | 依据与边界 |
| --- | --- | --- |
| 按媒体自然比例展示 | 已实现 | 图片 naturalWidth/Height、视频 metadata、素材尺寸依次推导；空结果读取目标画幅。比例逻辑与节点渲染检查通过。 |
| 节点等比例缩放并保存 | 已实现，拖拽待手动验收 | NodeResizer；宽度 160–720px，保存宽度、比例和位置。检查确认不增加语义 revision、不使下游失效。 |
| 放大预览后回原画布 | 已实现，视口与焦点待手动验收 | 原生 dialog 展示实际图片/视频；关闭不调用画布缩放、定位或重排。 |
| 可拖动、收起的创作面板 | 已实现，布局待手动验收 | 浮层不挤压画布；指针拖动、展开/收起、关闭/重开、容器变化边界约束。 |
| Prompt、模型、比例、质量 | 已实现 | 模型来自 `/api/status`；图片质量、视频时长与清晰度写入当前方法。检查覆盖保存与非法参数组合。 |
| @ 选参考图 | 已实现，键盘交互待手动验收 | 打开可搜索的当前创意素材列表，已引用项去重；无法使用的图片阻止保存。 |
| 拖拽引用、上传图片 | 已实现，拖拽与上传待手动验收 | 媒体拖拽柄和节点拖入面板；上传复用现有素材 API 并绑定来源。仅 JPG/PNG/WebP，最多 10 MB。视频需先提帧。 |
| 草稿保存与生成 | 已实现，真实生成未验收 | 本机缓存保留未保存草稿；显式保存写回方法，冲突提示后可读取最新版本；生成先保存再调用现有 Agent 入口。 |
| 点击 + 决定下一步 | 已实现 | 图片续做、视频、备选做法、比较、连接已有步骤。领域检查覆盖一次创建方案/步骤/结果占位、图片引用继承与无自动生成。 |
| 拖动连接已有步骤 | 已实现，指针操作待手动验收 | 图片连接同时写入 referenceIds 与 inputs，其他连接写入输入关系；服务端继续校验有向无环图。 |
| 比较真实结果 | 已实现入口，沿用既有比较方式 | 打开已有方案/方法比较抽屉；保留采用产物机制。画布内并排分组属于第三版。 |
| 精简工具条 | 已实现 | 常驻添加、选择、平移、适应画布、更多；制作路径、Skill、配方、整理、导出收进更多。 |
| 上下游关系聚焦 | 已实现 | 选中节点显示祖先与后续节点，无关节点/连线弱化；纯逻辑检查通过。 |
| 自动整理适应大图 | 已实现 | 显式整理读取测量尺寸；检查覆盖高图行间距与宽图列间距。新增分支尚未自动避让所有节点。 |
| 保留方案、历史、来源和保存机制 | 已保留，关键行为检查通过 | 历史产物不成为可编辑方法；备选保留原方法和结果；新步骤未执行时无 run；仍受现有用户选路规则约束。 |
| Native / 探索 / 研究三档 | 沿用现有实现 | 持久化 ID 仍为 0、1、3；旧 ID 2 兼容探索，本次不重写历史设置。 |

生成流程需要特别说明：已有选定路线且模型/工具匹配时执行当前步骤；新画布草稿或改变实现机制时先发起路线规划。在“用户选择”模式下仍需选择路线后执行。第二版没有绕过后端选路约束，也不会在拖图、新建节点或选择模型时自动调用生成。

## 检查结果与实际限制

- `npm run build`：通过，包含 TypeScript 类型检查；Vite 保留已有的超 500 kB 分包提示。
- `node --import tsx scripts/experiment-canvas-v2-check.ts`：通过。覆盖原子新建、继承引用、历史保护、显示尺寸持久化、参数保存与验证、备选保留、关系计算、实际尺寸布局，以及自定义媒体节点和创作面板的服务端渲染。
- Impeccable 静态检测：106 项 advisory，均为本局部深色主题相对全局设计规范的颜色、字号、圆角提示；没有其他类别的问题报告。该结果不能代替对比度、可读性和布局的浏览器验收。
- 按用户约束未使用 browser / computer use，未触发付费图片或视频生成。因此没有把拖拽手感、窄屏遮挡、预览回位或供应商真实返回标记为端到端通过。

手动确认时集中看五条：横/竖媒体缩放后刷新保留；拖动并收起面板后仍能找到入口；@ 与拖图引用后保存能重开；放大关闭后视口不动；新草稿点击生成后遵循当前选路策略。

## 第三版迭代清单

第三版应先解决创作流程连贯性，再增加视觉表达。以下为后续开发规格，尚未实施。

| 优先级 | 改进 | 第二版发现的原因 | 第三版验收条件 |
| --- | --- | --- | --- |
| P0 | 草稿、路线与执行节点连续 | 新草稿经路线规划后，既有架构会另行生成执行节点，原草稿仍保留。用户可能不知道该跟随哪组节点。 | 在保留选路约束的前提下，将批准路线明确关联或转换到原草稿；原位显示执行进展与新结果，避免重复的无说明占位。 |
| P0 | 区分参考图与执行依赖 | 图片拖入会同时增加引用与依赖；移除参考缩略图只移除 referenceId，结构依赖仍在。引用自身历史输出可能形成循环，当前由服务端拒绝。 | 在面板明确显示两类关系；移除操作说明影响；新增连接前提示循环；允许合理引用历史结果且保持执行图无环。 |
| P1 | 画布内比较与采用 | 第二版的比较入口仍使用抽屉，来回对照素材会离开当前图关系。 | 可在画布内并排比较同一步的真实结果、方法与参数，明确“采用”的对象及受影响下游。 |
| P1 | 新节点避让与视口连续 | 新分支按固定偏移放置，长竖图或多次分支可能重叠；新增节点触发现有适应画布逻辑。 | 新步骤/产物根据实际边界找空位，保持当前阅读位置，提供“定位新节点”；手工排布不被自动覆盖。 |
| P1 | 参数控件随模型能力联动 | 目前会在生成前拦截非法组合，但 MiniMax 时长/清晰度选项仍可能组合出不支持的值。 | 改变模型、画幅或清晰度时只提供可用组合；同步参考图上限，输入时就能理解限制。 |
| P2 | 节点内执行进展与恢复 | 目前沿用运行/失败标签及详情中的记录，长任务的排队、生成和失败恢复仍偏向对话操作。 | 从真实任务状态显示阶段和耗时；失败可查看原因、按现有服务能力恢复或重试，避免重复生成。 |
| P2 | 浮层可读性与快捷操作 | 小字号和多个浮层的实际遮挡尚未手动验收。 | 根据实际桌面及窄容器反馈调整字号、面板让位和键盘入口；先验收真实交互，再决定是否需要更多面板。 |

建议第三版先交付两个 P0，验收“同一个创作上下文能从编辑一直跟随到结果”，再推进画布比较与自动避让。

## 实现位置

- `src/ExperimentCanvasNode.tsx`：媒体节点、缩放、引用柄、预览入口和上下文连接点。
- `src/ExperimentCanvasComposer.tsx`：创作面板、参数、引用、草稿和保存/生成。
- `src/experiment-canvas-model.ts`：模型能力、比例、引用、参数校验和关系计算。
- `src/ExperimentWorkbench.tsx`：画布、上下文菜单、上传、预览、执行与现有工作流衔接。
- `src/experiment-canvas-v2.css`：第二版局部主题和响应式规则。
- `shared/experiment.ts`：display、resize、canvas-next 和测量尺寸布局。
