# 视频创作实验台：产品选择与第一版实现

## 产品判断

把 Codex App Server 嵌入产品，可以获得对话、工具调用、历史与流式事件等执行基础。能否完成同样的视频任务，还取决于系统指令、工具、文件工作区、依赖与媒体服务。它不会自动带来视频领域的状态管理与交互。

当前代码中最直接的能力限制是 `server/creative-agent-instructions.ts` 原本禁止 shell 和文件编辑，只开放固定的媒体 MCP 工具。原有画布也围绕镜头拆解、分镜图和视频生成组织。嵌入的 Agent 因此难以像通用编码 Agent 一样执行程序化视频 Skill。

用户选择平台的理由应当是：用更少的上下文解释、环境操作和重复制作，得到可检查、可修改、可继续、可复用的视频生产过程。对熟悉终端、只需一次性交付的人，直接使用 Codex 或 Claude Code 仍然合理；不必假设所有人都会被画布吸引。

## 三个方案

| 方案 | 交互与交付 | 价值 | 主要代价 |
| --- | --- | --- | --- |
| 任务驾驶舱 | 对话输入，按阶段展示任务、素材与结果 | 快速上手、容易交付 | 流程偏固定，探索过程表达有限 |
| 创作实验台 | Agent 动态组织方法、步骤、素材与阶段结果，用户可局部修改、创建备选 | 过程可操作、依赖可追溯、允许探索 | 需要可靠的领域数据模型与执行结果关联 |
| 配方工厂 | 验证过的流程参数化，替换素材后复用 | 适合稳定团队生产与后续批量化 | 没有成功探索的基础，容易过早固化错误流程 |

选择创作实验台，逐步形成配方工厂。任务驾驶舱可以成为以后面向轻度用户的简化视图。

## 产品结构

自然语言表达意图；Agent 选择与调整方法；实验图记录创作对象及依赖；执行层使用模型工具或本机程序化工作区；节点组件展示和编辑领域状态。

画布中保留五种对象：

- 素材：参考视频、商品图、人物参考或明确的文本创作输入。
- Skill：方法来源，保存仓库、SKILL.md 路径、完整文本与固定 commit。
- 步骤：真正要做的工作，保存目标、提示词、方法和输入。
- 产物：实际获得的脚本、代码、关键帧、视频与文件。
- 比较：保留两个制作方案及各自输出，并记录选用结果。

Skill 是方法依赖，素材是内容依赖，产物是执行证据。连线表达真实输入关系。无需把每条日志、每次工具查询都变成节点。

这里采用受约束的动态界面：Agent 发布结构化实验节点，前端根据节点种类生成媒体预览、参数编辑、方法详情和比较组件。已有 OpenUI / HTML 可以承担说明和临时工具；持久化的实验关系不依赖临时页面的 DOM。

## 第一版交互

1. 打开 `/lab`，选择已有创意或明确点击新建。已有创作 Agent 工作区也新增“创作实验台”标签。
2. 自然语言描述任务，或从程序化视频、热门口播、关键帧、整片提示词、九宫格、换人物六种路径开始。
3. Agent 可增删或重组步骤。路径仅为规划骨架，不代表这些能力已经调用。
4. 连接当前创意的素材，编辑节点里的目标、方法、提示词或文本结果。
5. 粘贴公开 GitHub 链接。多个 Skill 时选择具体文件；导入后固定 commit，可查看原文。选中步骤导入时自动连接方法依赖。
6. 在制作步骤中点“交给 Agent 继续”，任务写入对话草稿，由用户发送。节点内尚未保存的修改不会被误当作执行参数。
7. 现有媒体生成工具接受可选 `stepId`，提交前核对上游，提交后绑定真实任务和产物。
8. 方案拥有明确目标并逻辑组织步骤与产物，节点无需相邻。“创建备选方案”复制整条制作路径并保留共享输入；“备选方法”只增加同一步骤的另一份提示词、参考图和参数。比较面板分别支持方案对比和方法对比，可采用已完成产物。
9. 改变输入、提示词、方法或 Skill，保留旧结果并把相关下游标为需要更新。
10. 保存配方时区别流程草稿与已完成验证的流程。复用会新增一份流程，重置素材引用和执行结果，保留方法、参数和 Skill 版本。

## 程序化创作通道

本机模式允许 Agent 在 `data/agent-workspace/<creative-id>/` 编写代码、安装任务所需依赖并渲染。每个创意有自己的工作目录，实际工作由 Codex 内置 shell / 文件工具执行。GitHub 导入仅做方法读取，不会自动运行远程脚本。

`publish_experiment_file` 核对文件属于当前工作目录、真实存在且类型与大小受支持，再复制到媒体目录并生成可追溯的产物节点。视频读取真实媒体元数据；代码和 HTML 以纯文本文件提供，避免把源代码作为同源可执行页面打开。

这条通道默认只在本机模式开放，可用 `SOP_AGENT_PROGRAMMATIC_ENABLED=false` 关闭。独立目录不是 OS 沙箱，不能当成多租户安全隔离。公网模式暂不开放程序化执行；后续接入独立容器 / Worker 后再启用。

第一版没有预装和实跑每个第三方 Skill。Remotion、HyperFrames 等方法是否能够完成，仍取决于具体依赖和机器环境。配音、人物替换等服务也需要对应执行能力；不能用普通文生视频冒充。

## 数据与执行约定

- `shared/experiment.ts` 定义节点、图、配方、操作和无环依赖检查。
- `shared/experiment-organization.ts` 兼容迁移旧数据，并维护方案归属与当前方法。`plans` 保存目标、方案分支与采用结果；步骤的 `methods` 保存提示词、输入参考图、模型与参数；`runs` 保存每次执行的独立快照，产物通过 `runId` 追溯来源。
- 提交媒体任务时在服务端登记真实产物，重复绑定同一来源不新增结果。方法或输入变化保留历史产物，受影响的下游标为需要更新；旧任务恢复仍沿用原执行记录。
- 实验图保存在原有 Agent session 中，通过原有 SSE 与界面同步。
- UI 写入带图 revision，避免覆盖 Agent 或其他窗口的较新修改。
- 节点记录 revision 和完成时的上游 revision；修改沿依赖传播过期状态。
- `server/experiment-workbench.ts` 固定 GitHub 方法版本、核对素材归属并同步真实任务。
- `server/experiment-runtime.ts` 管理本机程序化工作目录与文件发布。
- `get_creative` 给出有界摘要，省去配方快照的完整重复内容；`read_experiment_node` 按需读取完整 Skill 和长文本。
- JSON 导出保留当前实验图与配方；跨项目导入、批量运行和成本记账尚未实现。

## 值得后续验证的产品假设

画布应帮助用户完成具体动作：定位失败步骤、替换一种方法、检查受影响范围、保留更好的方案和重复成功制作。用户不需要手工搭完 DAG 才能开始创作。

后续优先记录：第一次有效产物所需操作数、一次修改影响的重做范围、成功配方的实际复用率，以及中断后能否恢复上下文。真正的壁垒来自可靠的创作状态、素材版本和成功方法积累。
